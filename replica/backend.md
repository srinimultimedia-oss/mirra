# Server-backed collaboration

The `cloud/` checkout is a private Sites-hosted Vinext Worker. It preserves managed ChatGPT sign-in; production API handlers require dispatch-provided identity. Owner records use the stable Site user id. Board membership grants currently match the authenticated email, with editor/commenter/viewer roles. This is a partial access model: organization scopes, guest lifecycle, invitations, email-change membership reconciliation, protected locks, SSO and enterprise administration are unfinished.

Cloudflare D1 stores board documents, revision numbers, mutation receipts, memberships, presence, request limits and comments. Schema changes are append-only generated Drizzle migrations. No schema mutation occurs during request handling. Board writes validate the document and use a revision-guarded SQL transaction plus idempotency receipt. Access is checked again in the guarded write. Concurrent disjoint object fields merge; same-field changes produce a conflict response that preserves the device draft. This is not a fine-grained text CRDT, and drag/edit-session concurrency still needs broader stress testing.

GET /api/me identifies the signed-in visitor. GET/POST /api/boards lists/creates accessible boards. GET /api/boards/:id returns a snapshot. POST /changes applies field mutations. /members is owner-managed. POST /presence records a client cursor and removes expired clients; departure beacons remove the client's presence. GET /events streams canvas changes, people and comment updates. Comment endpoints support root threads, replies, author edits, removal, resolution and reopening; commenters cannot edit canvas content. Access revocation is checked while streaming. Temporary storage errors close the stream for reconnect without declaring permanent revocation.

Current transport checks the database about once per second using short-lived SSE streams. It is functional live synchronization, but its latency and capacity do not establish Miro-scale parity. Documents currently have an explicit 1.8 MB cloud limit to stay below D1's documented row limit; item-level sharding or another storage strategy is required for larger boards. See https://developers.cloudflare.com/d1/platform/limits/. Database batch transactions are used for guarded snapshot/receipt changes; see https://developers.cloudflare.com/d1/worker-api/d1-database/.

Device recovery drafts are saved before dispatch. Failed network updates retain the same operation id for retries. A draft export and explicit reload action are available. Distinct clients and revisions are covered by integration tests; the two browser clients used in local UI verification shared the loopback development identity. Distinct-user roles were tested using independent trusted identity fixtures, not forged hosted headers. Hosted verification must use a real signed-in browser.

No third-party API keys or live service credentials are embedded. Cross-origin writes are rejected; request rates, payload bounds and model validation apply server-side. UI disabling is supplementary; it is not the access boundary. Local SQLite fixtures are isolated from the hosted D1 database. The host's backup/restore configuration has not been independently verified, so backup validation remains open. Upload isolation, payments, provider integrations, notification delivery, audit trails, full deletion/export requests and production load testing remain unfinished.
